# Published reference runs

These are appliance measurements, not model-quality rankings. Every number is
generated by the protocol revision embedded in its result JSON.

## GLM-5.3-Flash, Libert NVFP4, TP2, low effort

Two DGX Sparks connected directly over 200 Gb/s RoCE, using the pinned Libert
NVFP4 checkpoint, FP8 E4M3 KV, native `flashinfer_cutlass`, and DFlash2 at
`k=7`.

| Measurement | Median | Range |
|---|---:|---:|
| Completed code decode | 44.0 tok/s | 43.2–45.4 |
| Completed prose decode | 18.3 tok/s | 18.1–19.1 |
| Valid structured decode | 67.3 tok/s | 63.3–67.6 |
| Cold 64K prefill | 1,920 tok/s | 1,919–1,922 |
| Warm 64K replay | 11,359 tok/s | 11,346–11,370 |
| C1 short code-load, end-to-end (256-token cap) | 28.2 tok/s | 23.7–29.2 |
| C2 short code-load, end-to-end (256-token cap) | 42.6 tok/s | 28.8–43.2 |
| C4 short code-load, end-to-end (256-token cap) | 59.5 tok/s | 44.6–69.1 |

All three decode workloads passed **5/5** completion gates. The roughly 3.7×
gap between valid structured output and completed prose on the same appliance
is why structured or counting prompts must not be presented as everyday agent
speed.

Run command:

```bash
python3 bench.py \
  --base-url http://HEAD:8000 \
  --model auto \
  --label glm53-libert-nvfp4-tp2-low \
  --comparison-id 2026-09-05-glm-topology-sweep-2 \
  --metadata metadata.json \
  --extra-body '{"chat_template_kwargs":{"reasoning_effort":"low"}}'
```

The [complete result](results/reference/glm53-libert-nvfp4-tp2-low.json)
contains the immutable benchmark revision, appliance metadata, every raw run,
visible generated answers, hashes, TTFTs, prefill samples, and concurrency
tails. The endpoint address and credentials are deliberately absent.
